# P2P server engine 复用

## 背景与现状

大厅协商后的多个 P2P 连接可能复用同一个大厅 UDP socket，一个客户端也可能在多次协商中都担任 server。当前 `example1/p2p_peer.cpp` 每次调用 `GSY_StartP2PPeer` 都为该 peer 创建独立的 `P2PDatagramEngine`，即使多个 server peer 使用的是同一个 socket。每个 engine 持有自己的接收回调、地址白名单和连接回调；peer 结束后会等待其 engine 的连接全部关闭，再销毁 engine。

复用同一个大厅 socket 有利于保留已有的本地端口和 NAT 映射，但不能保证所有网络环境下打洞成功。同一个 socket 上的 server peer 可以考虑复用 server engine，减少重复资源，并由一个 engine 管理多个入站 QUIC 连接。单纯本地端口相同不足以证明可以复用：必须确认是同一个底层 socket，且 engine 的配置兼容。

目前已有并发测试覆盖同一 socket 上额外 peer 的创建与关闭；它不证明多个有效的 server peer 已共享 engine。mqas 的 TLS 上下文缓存已调整为按引用计数释放，这解决独立 engine 的共享 TLS 资源生命周期问题，不等同于 engine 复用。

## 拟定设计

### 共享 engine 与生命周期

- 在 SDK I/O 线程维护 server engine 注册表。以底层 socket 的稳定身份和经过规范化、影响 engine 行为的配置为复用条件；配置不兼容时明确返回错误或创建独立实例，具体策略在实现前结合 socket 接收分发能力确定，不能静默复用不兼容配置。不要仅以数值 socket handle 或端口作为长期身份，避免 handle 失效、复用或不同 socket 混淆。
- 引入共享 server engine 对象，持有 socket、engine 及其接收回调；peer 持有共享对象引用，并各自保留协商结果、认证材料、定时器、连接和调用方回调。
- 每个 peer 独立取消、超时和关闭。关闭一个 peer 只关闭其所属连接并移除其等待信息；其他 peer 的连接、回调和定时器不受影响。
- 最后一个 peer 移除且 engine 的连接和待处理回调清理完成后，再销毁 engine 和释放 socket。关闭 SDK 时先停止接收新的启动请求，再逐个结束 peer 并等待共享 engine 清理完成，避免在 lsquic 回调栈内销毁 engine 或阻塞 I/O 线程。
- 启动、连接路由、超时和清理由 I/O 线程串行执行；公开入口对跨线程访问的注册表和关闭流程保持必要同步。调用方回调可能重入关闭操作，需要保持终态回调最多一次。

### 入站连接归属与认证

- server engine 的新连接回调需要路由到正确的待连接 peer。对端 IP 和端口可作为初步匹配信息，但不是身份凭据：可能存在同一地址对应多个并发协商、NAT 映射变化及地址伪造等情况。
- 如果某个地址对应多个待连接 peer，不能按到达顺序或任意选择来绑定。应先确定握手后能够携带并验证协商身份的协议，例如携带协商产生的会话标识并验证对应 token；确认协议支持和安全属性后，再将连接确定归属到唯一 peer。对无法唯一匹配、验证失败或超时的连接执行隔离清理。
- 当前 token 校验位于 Datagram 业务 stream 阶段，而 `on_connected` 表示传输层握手完成。实施时须明确认证之前如何承载和限制 stream、何时通知调用方连接已建立，以及失败回调语义；不要把地址匹配或 QUIC 握手成功当作身份认证。若需要调整公开回调语义或协议，应单独评审兼容性。
- 等待连接的计时器属于 peer，不属于共享 engine。一个 peer 握手成功、超时或被取消，不能停止其他 peer 的计时器或删除其他 peer 的认证材料。

### 地址过滤

当前 `mqas/mqas/src/core/engine_interface.cpp` 中 IP 白名单和端口白名单分别检查。多个地址共享 engine 时，这会允许两个列表的交叉组合；应改为按完整的地址族、IP 和端口组合匹配，并处理共享地址的引用计数或按 peer 管理的移除，避免一个 peer 关闭后影响其他 peer。地址过滤只是入口约束，不替代 token 验证。

## 实施步骤

1. 梳理大厅协商结果、NAT 地址、连接回调可获取的信息，以及现有 Datagram 认证协议；确定可唯一标识并验证会话的方法和超时策略。
2. 设计共享 engine 注册表、配置兼容性规则和 peer/连接状态机；确定认证与公开回调的语义。
3. 实现地址对过滤及安全移除；引入共享 server engine，对入站连接完成路由、认证和独立清理。
4. 保持 client peer 启动流程和现有 socket handle 所有权约定；检查 SDK 终止与回调重入。
5. 增加测试：同一 socket 上两个真实 server peer 同时连接并通信；关闭其中一个后另一个继续通信；不同启动顺序、独立超时和取消；相同对端地址的并发协商、错误 token、地址交叉组合过滤；最后一个 peer 释放和 SDK 终止。覆盖不同 socket 或不兼容配置不得错误复用的情况。
